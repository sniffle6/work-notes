## Highlights

- Jira stays readable in smaller windows, with more room for ticket titles and details.
- Unfinished ticket drafts, comments, and edits now survive restarting Work Notes.
- Review proposed Jira changes field by field before approving them.

## Changes

### Jira Workspace

- Ticket titles use the full row width, with quieter metadata underneath. Collapse status groups or sort titles alphabetically within each status.
- Opening the agent in a smaller window makes room for it by hiding the ticket list. Narrow windows show the list, ticket, or agent one at a time, with controls to switch between them.
- Toolbars stay on one line and use labeled icons when space is limited.

### Drafts And Unfinished Writing

- New-ticket drafts, unsent comments, and ticket edits save locally, separately for each Jira site and project.
- Choose "Keep for later" to browse tickets without losing a draft, then "Resume draft" to return to it. Discarding or successfully submitting clears the corresponding saved writing.
- Undo the agent's latest draft rewrite until you edit again. Late agent replies cannot overwrite a replacement draft, and undo history does not carry across Jira projects.
- Storage failures show an error and a retry action. If saved writing cannot be loaded, Work Notes keeps it intact instead of replacing it.

### Proposal Review

- New proposals show the fields being changed, with previous and proposed values for ticket edits, status changes, and assignments. Comments and new tickets show the content to be added.
- Reviews identify unavailable comparisons and warn when replacing a description may remove Jira formatting. Previous values are snapshots taken when proposed; Jira may change afterward.
- Proposals distinguish waiting for approval, applying, applied, rejected, and failed states. Failed changes do not retry automatically.
- A proposed new ticket keeps the project shown in its review, even if the default project changes before approval.

## Install And Update Notes

- Windows installer is attached to the GitHub release.
- Existing installs update from the latest-release `latest.json` after publish.
- Drafts are stored on this device and are not sent to Jira until submitted. Save failures are shown in the Jira view.
- Draft rewrite undo history lasts for the current app session. Older proposals remain usable but do not have saved before-and-after comparisons.
